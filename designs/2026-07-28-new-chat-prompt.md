## Главная задача — залипание D-Pad на главной, НЕ ПОЧИНЕНО

На ТВ курсор залипает вверху главной страницы: ни вниз, ни вверх не идёт, влево
при этом открывает боковую панель.

Прошлая сессия выдвинула гипотезу про `LazyRow` (ряды ниже экрана — заглушки без
фокусируемых элементов, мёртвая петля «фокус не двигается → страница не
скроллится → заглушка не монтируется»). Фикс `5aa3d69` подталкивает страницу и
расширяет запас предзагрузки. **Я поставил эту сборку — не помогло.** Гипотеза
не подтвердилась.

### Что уже проверено на эмуляторе (не трать на это время заново)

Через CDP к WebView:

- у каждого ряда ровно один tab stop, геометрия рядов ниже нормальная
  (`offsetParent` есть, `tabIndex` 0, вменяемые прямоугольники);
- `activeZone` = `main`, в зоне 553 элемента, 33 проходят фильтр, текущая
  карточка в зоне;
- прямой вызов `SpatialEngine.move('ArrowDown')` находит следующий ряд и
  переводит фокус;
- синтетические `keydown` на `window` проходят ряды 0 → 22;
- на чистом старте физические нажатия D-Pad тоже проходят 0 → 8, все 8 клавиш
  видит capture-listener.

То есть **на эмуляторе движок работает и клавиши доходят**. Что делает иначе
реальный ТВ — не выяснено.

### Два ложных следа, не повторяй

1. Кнопки топбара **зарегистрированы** в spatial-навигации (`App.jsx:196`,
   `useSpatialItem('main')`). В прошлый раз я заявил обратное, потому что грепнул
   только класс `focusable` и не проверил объявления ref'ов.
2. «Залипание», которое я дважды воспроизвёл, оказалось системным диалогом
   `GrantPermissionsActivity` — он висит поверх после debug-установки и съедает
   D-Pad. Всегда проверяй `adb shell dumpsys window | grep mCurrentFocus`,
   прежде чем делать вывод.

### С чего начинать

Начни с **замера на устройстве**, а не с новой гипотезы. Нужен эмулятор
(AVD `Television_4K`) или `adb` до ТВ — спроси меня, я подниму.

Рецепт снятия DOM с устройства:

```bash
# release-сборка отладку WebView не отдаёт — нужна debug
cd client/android && ./gradlew assembleDebug
adb uninstall com.torserve.pwa && adb install app/build/outputs/apk/debug/app-debug.apk
# заранее выдать разрешение, иначе диалог украдёт D-Pad
adb shell pm grant com.torserve.pwa android.permission.RECORD_AUDIO
# пробросить CDP
adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>   # pid из /proc/net/unix
```

Для WebSocket к CDP нужен `websocket-client` и `create_connection(..., suppress_origin=True)` —
иначе DevTools отклоняет handshake с 403.

Полезно снять: доходят ли `keydown` (capture-listener на window), что
возвращает `findNearest` в момент реального нажатия, и где оказывается
`document.activeElement` до/после.
